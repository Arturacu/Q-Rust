# Dense Clifford20 routing diagnostics

This exploratory investigation keeps production compiler commit `3306937c0ae71fb2eb78ad86141f2ccd1b636465` and binary SHA-256 `aa6513a05aa814b8b89cf373472cacaef4a0afa7c66a296d76a67ef4f4824e1e` unchanged. Source links are pinned to repository head `3327d6cdcd937f3a3786c756a0279cf99e522239`, which contains that compiler and the preceding results. The circuit is an existing development fixture, so these controls provide causal diagnostics rather than held-out evidence.

The baseline uses one warmup and three measured repetitions for each profile mode and each target. All 16 outputs pass the frozen map-aware Clifford Choi-isometry checker. Every native response is identical across modes/repetitions except `compile_ns`, `parse_ns` and `pass_diagnostics`; the separate controller timing/cold-worker fields are excluded explicitly. The native compiler, oracle and fixture hashes are bound in `baseline_trace/protocol.json`.

For each profiled request, disjoint trace events are summed into groups, then divided by that request's compilation time. The median of those three shares is 83.69% / 89.89% for beam routing, 6.43% / 3.43% for layout search, 1.29% / 0.71% for local Clifford simplification and 0.97% / 0.71% for two-qubit block synthesis (square / heavy-hex). All saved trace events cover 99.81–99.83% / 99.88–99.89% of their requests. These are diagnostic observations with profiling enabled; stage medians are never added together and presented as an exact partition of the median compilation time. `analyze_dense.py` reproduces the per-request calculations in `baseline_accounting.json`.

The frozen final-output selection policy routes two different prepared continuations. On square, the rewritten continuation wins with cost `[4416,2464,2017]` over the retained original `[4491,2795,2223]`. On heavy-hex, the retained original wins with `[7898,3612,3138]` over the rewritten continuation `[8050,3600,3134]`: the rewritten route improves depth slightly but adds CX. These are final lowered costs, not routing SWAP proxies. The completed intervention disables Clifford simplification and its retained-input comparison together: its median time is 49.6% of the within-block reference on square, but it loses 75 CX and 331 total depth; on heavy-hex its time is 48.2% and the exact output QASM/maps match the reference. This measures the complete pipeline consequence of the toggle. It does not prove two separately routed continuations are inherently necessary for a quality guard, or establish a general way to choose the successful branch in advance.

## What the source establishes

| Repeated forward/backward search | [routing.rs:994](https://github.com/Arturacu/Q-Rust/blob/3327d6cdcd937f3a3786c756a0279cf99e522239/src/transpiler/routing.rs#L994), [routing.rs:1053](https://github.com/Arturacu/Q-Rust/blob/3327d6cdcd937f3a3786c756a0279cf99e522239/src/transpiler/routing.rs#L1053) | Each nonsplit O3 route invokes four forward and three backward beam searches. The complete square/heavy-hex fixtures have no routing fences that split this loop. The two distinct Clifford continuations each execute this procedure. |
| Candidate SWAP enumeration | [routing.rs:529](https://github.com/Arturacu/Q-Rust/blob/3327d6cdcd937f3a3786c756a0279cf99e522239/src/transpiler/routing.rs#L529) | For every active beam, candidate edges touch either endpoint of a front-layer gate; edges are sorted and deduplicated before scoring. More front gates and incident edges can increase candidate work. This is a mechanism, not an experimentally fitted scaling law. |
| Lookahead and score recomputation | [routing.rs:370](https://github.com/Arturacu/Q-Rust/blob/3327d6cdcd937f3a3786c756a0279cf99e522239/src/transpiler/routing.rs#L370), [routing.rs:407](https://github.com/Arturacu/Q-Rust/blob/3327d6cdcd937f3a3786c756a0279cf99e522239/src/transpiler/routing.rs#L407) | Each active beam constructs one deterministic extended layer and shares it across candidate scores. Every candidate score scans front/extended gates and uses table lookups for shortest-path deltas; it skips distance arithmetic for interactions untouched by the candidate. The lookahead-size intervention tests this combined search/quality effect. |
| Distances are precomputed | [routing.rs:956](https://github.com/Arturacu/Q-Rust/blob/3327d6cdcd937f3a3786c756a0279cf99e522239/src/transpiler/routing.rs#L956), [backend.rs:283](https://github.com/Arturacu/Q-Rust/blob/3327d6cdcd937f3a3786c756a0279cf99e522239/src/backend.rs#L283) | A breadth-first search from each physical vertex constructs the distance table once per route invocation. Candidate scoring uses this table. Recomputing a shortest path for every candidate is therefore not an explanation of this implementation's overhead. |
| Child-state copying and ranking | [routing.rs:302](https://github.com/Arturacu/Q-Rust/blob/3327d6cdcd937f3a3786c756a0279cf99e522239/src/transpiler/routing.rs#L302), [routing.rs:580](https://github.com/Arturacu/Q-Rust/blob/3327d6cdcd937f3a3786c756a0279cf99e522239/src/transpiler/routing.rs#L580), [routing.rs:588](https://github.com/Arturacu/Q-Rust/blob/3327d6cdcd937f3a3786c756a0279cf99e522239/src/transpiler/routing.rs#L588) | Each candidate child clones layout, accumulated actions, dependency counts and front layer. Progress ranking executes free gates, sorts children, and deduplicates keys that themselves clone layout/dependency/front vectors before truncating to eight states. Allocation/copying could be costly on long dense circuits; no allocation-level profile has isolated its share. The rank-progress toggle changes search semantics as well as bookkeeping. |
| Conditional branching and truncation | [routing.rs:573](https://github.com/Arturacu/Q-Rust/blob/3327d6cdcd937f3a3786c756a0279cf99e522239/src/transpiler/routing.rs#L573), [routing.rs:646](https://github.com/Arturacu/Q-Rust/blob/3327d6cdcd937f3a3786c756a0279cf99e522239/src/transpiler/routing.rs#L646) | Up to five children per active beam are expanded when the best heuristic delta is negative; otherwise branching is one. Thus eight states can expand to at most forty children at a step, but forty is an upper bound, not an observed constant. |
| Retained routing alternatives | [routing.rs:1026](https://github.com/Arturacu/Q-Rust/blob/3327d6cdcd937f3a3786c756a0279cf99e522239/src/transpiler/routing.rs#L1026), [routing.rs:1111](https://github.com/Arturacu/Q-Rust/blob/3327d6cdcd937f3a3786c756a0279cf99e522239/src/transpiler/routing.rs#L1111) | Equal-SWAP candidates can be reconstructed and compared for depth. At most one extra forward search explores a previously unvisited refined layout within one SWAP of the best routing proxy. Distinct retained candidates receive independent lowering and final validation. This trades compilation work for final output quality. |
| Layout budget | [layout.rs:411](https://github.com/Arturacu/Q-Rust/blob/3327d6cdcd937f3a3786c756a0279cf99e522239/src/transpiler/layout.rs#L411) | Default layout uses ten trials and up to three forward/backward refinements, memoizes identical routes and stops at zero SWAP cost. These dense cases report 70 distinct greedy layout evaluations for each prepared continuation. The diagnostic field is carried into later pass snapshots; summing that repeated field across all events would overcount. |

The profile demonstrates where elapsed time is spent and that the two continuations differ. Source inspection explains the work performed inside the dominant pass. The completed 48 Q-Rust intervention requests all passed the frozen map-aware all-input Clifford check. Disabling progress ranking roughly halves runtime on both targets: it improves all three costs on heavy-hex, but increases square CX by 222 while lowering both depths. Reducing layout budget increases CX on both targets; shorter lookahead improves heavy-hex but worsens square. Disabling blocks worsens CX and both depths on both targets, with small observed runtime changes. These are selected fixed-seed counterfactuals on one existing logical circuit, not universal improvements. `FINDINGS.md` and the hash-bound `causal_findings.json` contain the exact cell medians and outcomes.

The 64 SDK controls are also complete: 24 outputs passed, 32 remain unverified because local non-Clifford U3 decompositions fall outside the frozen Clifford recognizer, and 8 original-Cirq heavy-hex requests exceeded the 30-second cap. Available native/instrumented artifacts and maps match exactly. TKET's initial FullPeepholeOptimise occupies 95.53%/93.93% of profiled square/heavy-hex compile time. Its lighter replacement saves substantial time but increases final CX and depth. Cirq's square trace is dominated by target-gateset synthesis, especially the postrouting stage; reducing synthesis passes changes observed time and output, but does not resolve its unsupported correctness check. Qiskit's callback trace is dominated by SabreLayout; no matched Qiskit internal-search-budget intervention was performed. These SDK stage results explain differences between the selected recipes without establishing a complete language-level or algorithm-level speed attribution.

Per-operation allocation costs, the causal contribution of every internal data structure, optimality of the output, language-level speed advantages, and general scaling to other workloads remain unestablished. The exact initial SDK plan and its source-eligibility-based pre-execution revision are both retained; the restricted native-CX arm was never executed. All 13 evidence-integrity regression tests passed. Production compilers, adapters, oracles and preceding results remain unchanged.
